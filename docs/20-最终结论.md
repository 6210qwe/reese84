# 最终结论：补环境走到边界了

写于 2026-10-18 05:45。连续十轮之后。这篇只做三件事：
**列清楚试过什么、明确哪些路已经堵死、给出唯一还能走的方向。**

---

## 一、这一轮修掉的真实 bug（有进展，但不够）

### bug：`putImageData` 收不到真正的 ImageData

```
[env] !! ctx.putImageData 异常: Failed to recover `ImageData` type from napi value
```

`getImageData` 我返回的是普通对象 `{width,height,data}`，
而 `putImageData` 需要 `@napi-rs/canvas` 导出的 `ImageData` 实例。
异常被 `catch` 吞掉，表现是 **sensor 画在 canvas 上的内容从来没真正写进去**。

修的时候又踩了一层：在 `02-media.js` 里 `require('@napi-rs/canvas')` **在 vm 上下文里不可用**
（vm 里没有 `require`），抛 ReferenceError 又被 catch 成 null。
必须从 `bridge` 注入：

```js
// bridge.js（Node 侧）
let __NapiImageData = null;
try { __NapiImageData = require('@napi-rs/canvas').ImageData || null; } catch (e) {}
// 暴露给 vm
{ ImageData: __NapiImageData }
```

修完后 payload 从 22000 **涨到 24228**（+2228 字节）——证明这块数据之前一直是空的。

### bug：`MAX_VIEWPORT_DIMS` 返回标量

`getParameter(3386)` 该返回 `Int32Array([32767, 32767])`，
我的参数表里根本没有 3386，于是走到兜底 `return 8`。

顺带修正：`36347`（MAX_VERTEX_UNIFORM_VECTORS）真实值是 **4095** 不是 4096。

### bug：`let` 的 TDZ 让回调静默失效

```js
// 第 206 行（使用）
if (typeof __onScriptsDone === 'function') { ... }
// 第 358 行（声明）
let __onScriptsDone = null;
```

`let` 有暂时性死区，`typeof` 对 TDZ 变量**同样抛 ReferenceError**，
被 `try/catch` 吞掉 → 表现成"回调永远不触发，日志里什么都没有"。

**这是这一路上第四次"写了但走不到"的坑**：
`__installCtx2D` 忘调用 / `baseline` 没挂到 cfg / 导出代码塞进 `if` / 现在的 TDZ。

共同特征：**不报错、不告警、静默失效**。
以后写补环境，只要出现"改了代码数字没动"，先按这四个模式查一遍。

## 二、这一轮排除的假设

### 假设 1：鼠标事件缺失（❌ 排除）

sensor 确实监听了一整套：

```
document: mousemove/mousedown/mouseup/mouseover/mouseout/mouseenter/mouseleave/dblclick
document: touchstart/touchmove/touchend/touchcancel
document: driver-evaluate / webdriver-evaluate / selenium-evaluate   ← 反自动化钓饵
```

实现了贝塞尔轨迹派发（12~25 点），验证 `MouseEvent` 本身正常（监听器确实收到），
分别在三个时机试过：

| 时机 | 结果 |
|---|---|
| `load()` 返回后 | payload 不变 |
| `load()` 内部、脚本执行完 | payload 不变 |

**而且关键反证：iv8 也从没派发过任何鼠标事件，它照样通过。**
⇒ `events.mouse` 为空不是判据。这条假设排除。

### 假设 2：payload 明文可对齐（❌ 排除）

hook `btoa` 之后发现它被调用 **1906 次**，输入总长 18145 字节。
但把全部输入拼起来看，**没有字段结构**：

```
false[object Window]128[object Window]0false[object Window]...
aaaaaaaaaaaa...（大量填充）
```

`[object Window]` 只出现 5 次，都在开头的探测性编码里。
后面全是填充字符 —— 说明 payload 是**分块编码**的，
btoa 的输入只是中间产物，拼起来不还原明文。

⇒ 这条路要往下走，只能 hook JSVMP 内部的字节码指令，那是逆向工程，不是补环境。

### 假设 3：环境值不对（❌ 已在上轮排除）

`--iv8-profile` 把 iv8 的 UA/屏幕/语言/时区/WebGL/canvas/字体/mimeTypes 全套照抄，
仍 B12。

## 四、剩下唯一没排除的差异

**执行模型。** 具体说：

| | iv8 | 我们 |
|---|---|---|
| 脚本执行 | `page.load()` + **14 轮 `eventLoop.sleep(600)`** | `load()` 同步一把跑完（1082ms） |
| 总虚拟时间 | 8.4 秒 | 1 秒 |
| 环境层 | C++ 实现的 window（可被 JS 微调） | 纯 JS 对象 |

iv8 那 14 轮 sleep 不是装饰：每一轮都会让 pending 的 `setTimeout` 回调执行，
sensor 可能在其中某些轮里做了额外采集。

我们已经确认 POST 是异步的（`load内已POST=否`），
所以理论上还有窗口 —— 但**只推进等待而不改变"采集时机"**是没用的，
真正需要的是让 sensor 的每一轮采集都发生在"已经有事件数据"之后。

这需要在 JSVMP 里找到一个可插入的时机点，而不是在环境层加钩子。

---

## 五、所以：这条路到此为止，原因是成本

不是"再补一个 API 就好"。剩下的活是：

1. **逆向 JSVMP**，定位到 38 个字段组装、序列化、加密的具体指令位置
2. 在每个采集阶段之间插入可控的事件派发
3. 或者：**自研一个能精确控制异步调度的 JS 引擎**（CSDN 那篇的 Rust 路线）

这两件事都是**月级工程量**，而且第 1 件做完之后仍不保证能过
（服务端可能校验了别的我们没有的东西）。

按投入产出比，**继续在补环境上试参数已经是负收益**。

## 六、可用的方案（都已验证）

### 方案 A：iv8（Python）

```bash
cd iv8 && python -X utf8 solve_iv8.py
```

实测 100% 通过，`/api/` → 404 len=9。单次 15~25 秒（含下载 837KB sensor）。
`--no-page` 只要 token。

### 方案 B：浏览器 + token 池（Node）

```bash
node tools/token_pool.js --serve 8899
curl 'http://127.0.0.1:8899/token?host=book.airgreenland.com'
```

冷启动 9.9 秒，之后 12 分钟免解，取 token 0ms。
`X-Iinfo: NNNN CT(...) q(0 0 5 -1) r(8 8) U11` —— 干净通过。

限制：需要有头 GUI 环境（无桌面的服务器跑不了）。

### 两个都不合适时

- 无 GUI + 要并发 → 用 iv8（Python 侧并发，多进程）
- 有 GUI + 要低延迟 → 用 token 池
- 要"既快又不依赖 GUI" → 只能自研引擎（月级）

## 七、这十轮的方法论总结

### 定位类

1. **真值只能从"能通过的实现的请求体"里读。** 我拿一个探针量出来的 7083 当靶子，
   调了一整天，那个数字根本不是 payload 字段。
2. **照抄"验证过能过"的实现的所有可观测值，是成本最低的定位手段。**
   dump 一次 iv8 环境，就推翻了 canvas 真实渲染、字体度量对齐、WebGL 扩展完整
   三个方向 —— 而这三项占了此前工作量的一大半。
3. **判据要选最早能拿到的那一个。** POST 响应头 `X-Iinfo` 是 3 秒，
   业务验证 GET 是 20 秒。选对判据，迭代速度差一个数量级。
4. **同会话换 body 是最强对照实验。** 把网络、会话、TLS 全固定住，只剩载荷一个变量。

### 判断类

5. **"拿到 token"永远是假阳性。** 服务端判你 bot 的时候照样返回格式完全正确的
   1254 字符 token。
6. **区分"值不对"和"动态行为不对"。** 值全对齐还不过，就别再翻值了，
   去查事件序列和采集轮次。
7. **空数据本身就是特征。** `events.mouse: []` 不是"少个可选字段"，
   是"这个用户从没动过鼠标"。
8. **挂不上时要区分"对象是原生的"和"挂错了位置"。** 判断方法：实例和原型各试一次
   defineProperty。我把后者当成前者，白丢一整轮。

### 工程类

9. **"写了但走不到"是补环境最大的坑，这一路踩了四次。**
   `__installCtx2D` 忘调用 / `baseline` 没挂 cfg / 导出塞进 `if` / `let` 的 TDZ。
   共同特征：不报错、不告警、静默失效。
   **对策：每次改完都问"这个改动如果生效，哪个可观测数字会变"，然后去看那个数字。**
10. **别做"看起来在推进"的实验。** 给 `Date.now` 加常数偏移不改变差值、
    给时钟做分段压缩只改形态不改校验 —— 这类实验跑一整天也没有信息量。
11. **探针本身会改变观测结果。** 不做调用来源过滤，统计出来的全是噪声
    （572 次 `canvas.width` 全是我自己实现读的）。
12. **穷举到一个明确的物理边界，就是可以停的信号。** 这十轮的前九轮都在
    "再试一个"，那不收敛；只有把 15 条假设逐条排除完，路线的取舍才第一次清晰。
