# 照抄 iv8 的环境值之后，仍被拦

这一轮的结论有两层：**先修正上一轮的错误，再给出新的确定结论。**

---

## 一、先认错：上一轮的"C++ 原生改不了"是错的

上一轮我把探针挂在 `Navigator.prototype` 上，一条都没记录到，
于是判断「iv8 的 window 是 C++ 原生、JS 包装挂不上」。

这轮直接测了：

| 探测项 | 结果 | 含义 |
|---|---|---|
| `navigator.userAgent` 在**实例**上 defineProperty | **P-INST** | ✅ 能改 |
| 同上，在 `Navigator.prototype` 上 defineProperty | 原始值 | ❌ 改不了 |
| `canvas.toDataURL` 替换 | **YES** | ✅ 能改 |
| `measureText` 替换 | **12345** | ✅ 能改 |
| `Function.prototype.toString` 替换 | **P-TOSTRING** | ✅ 能改 |

关键：`Object.getOwnPropertyNames(navigator)` 返回 `[]` —— **navigator 没有自有属性，全在原型上**。
而原型上改成不生效，说明 C++ 层直接返回原值、绕过原型链。
但**实例上 defineProperty 就生效**（自有属性优先级更高）。

所以结论要改成：

> iv8 的环境是 C++ 提供、**且可以被 JS 微调**的。
> 我的探针挂错了位置（挂原型而不是实例），不是"挂不上"。

这个修正很重要，因为它意味着：**照抄 iv8 的环境值是可行的**，而不是"只能接受它的黑盒"。

### 三个最反直觉的点

**1. `canvas.toDataURL()` 返回空字符串。**

```
canvas = { lenA: 0, hashA: '0', lenB: 0, hashB: '0', prefixA: '' }
```

iv8 的 canvas **完全不做光栅化**。而我用的是真实 Skia 渲染 + PNG 编码，
还为"PNG 长度怎么和 Chrome 对上"调了很久。

⇒ **服务端根本不看 canvas 像素。** 我在那上面花的功夫全部无效。

**2. `measureText` 的公式是 `width = 字符数 × 8`，与字号、字体族完全无关。**

实测 10px / 72px / sans-serif / monospace / serif / Arial 结果**全一样**：

```
sans-serif|72|13|104      monospace|10|13|104      serif|12|36|288
```

于是字体探测算法（候选族 vs generic fallback 量宽度、不同即认为装了）必然得到
**0 个已装字体**。

我用真实 Skia 渲染，探测出一大批真实字体——那是服务端没见过的组合。

**3. `getSupportedExtensions()` 返回空数组。**

我原来给了一份完整的 WebGL 扩展名单（30 多个），iv8 一个都不给。

⇒ 这三条合起来说明一件事：**iv8 的环境是"空壳"，而它能过。
服务端校验的不是这些值的真实性。**

## 四、新发现：sensor 监听了一整套鼠标/触摸事件

在探针里加上 `addEventListener` 包装后，拿到 sensor 注册的事件清单：

```
document: mousemove / mousedown / mouseup / mouseover / mouseout
          mouseenter / mouseleave / dblclick
document: touchstart / touchmove / touchend / touchcancel
document: online / pageshow / visibilitychange
document: driver-evaluate / webdriver-evaluate / selenium-evaluate   ← 反自动化
```

最后三个是**主动反自动化检测**：它监听这几个自定义事件名，
如果外部（Selenium/Puppeteer 的 evaluate 机制）派人派发这些事件，就暴露了。

而 payload 的 schema 里恰好有 `events.mouse` 和 `events.touch` 两个字段。
**我们从来没派发过任何鼠标事件**——`events.mouse` 是空数组。

真实用户不可能"一次鼠标都没动过"，所以空 mouse 轨迹本身就是 bot 信号。

### 试了，但没生效

实现了 `--mouse-trail`：用二次贝塞尔生成 12~25 个点的平滑轨迹
（每点 8~40ms 间隔，带 mouseover/mousedown/mouseup/mouseout），
在页面脚本执行完后派发。

验证过 `MouseEvent` 本身是好的：

```
{"evType":"mousemove","clientX":123,"screenX":123,"timeStamp":32.3,
 "bubbles":true,"received":1}   ← 监听器确实收到了
```

但 payload 不变（21996 vs 21992）。

**原因是执行模型**：sensor 在同步 `eval` 里就跑完了采集和上报，
我们派发鼠标的时机在它之后。真实浏览器里 sensor 之所以能采到鼠标，
是因为它内部用 `setTimeout` 分阶段，阶段之间用户真的在动鼠标。

iv8 是靠 `eventLoop.sleep(600) × 14` 推进了 14 轮异步窗口才做到的。
我们的 `load()` 是同步一把跑完，没有这个窗口。

**这条差距是架构级的，不是补几个 API 能解决的。**

## 五、现在还剩什么差距

| 项 | iv8（通过） | 我们（iv8-profile） |
|---|---|---|
| payload 长度 | 27912 | **21992（少 5920 字节）** |
| `events.mouse` | 有数据 | **空** |
| 异步窗口 | 14 轮 `sleep(600)` | 0（同步 eval） |
| 环境值 | 已全部照抄 | ✅ 一致 |

**5920 字节的缺口，最可能来自两部分：**

1. `events.mouse` / `events.touch` 的轨迹数据（每条事件约 30~50 字节、
   十几条就几百字节，但也可能 sensor 采了更多）
2. sensor 在多轮异步窗口里反复采集的累积数据

要补上，只有一条路：**让 sensor 的执行变成"分阶段 + 每阶段之间可派发事件"**。

具体做法是把 `env.load()` 改成：

```js
// 现在：一把同步跑完
env.load(ch.text, ENTRY);

// 需要：脚本执行 → 推进事件循环 → 派发鼠标 → 再推进 → 直到 POST
env.loadScripts(ch.text);          // 只执行 <script>，不跑定时器
for (let i = 0; i < 14; i++) {
  env.page.driveEventLoop(600);    // 推进一轮 setTimeout
  env.page.mouseTrail({ fast: true });
}
```

但这里有个前提问题：**sensor 的 POST 是在同步执行里发的，还是某个 setTimeout 里？**

从实测看，POST 发生在 `load()` 返回之后（日志里 `[4.9]` 在 `[5]` 之前、
`[6]` 之后才拿到 POST），所以**POST 确实是异步的**。

那说明还有机会：如果我们把 `load()` 拆开，在同步部分跑完后立刻派发鼠标、
再推进定时器，sensor 上报时就能看到鼠标数据。

**这是下一轮唯一值得做的事。**

## 六、这一轮的方法论收获

1. **挂不上时要区分两种原因。**
   "对象是原生的"（永远挂不上）和"挂错了位置"（换实例就成）。
   我上一轮把后者当成了前者，白丢了一整轮。
   判断方法：分别在实例和原型上试 defineProperty，看哪个生效。
2. **照抄"验证过能过"的实现的所有可观测值，是成本最低的定位手段。**
   这轮 dump 一次 iv8 环境，就推翻了三个此前的错误方向
   （canvas 真实渲染、字体度量对齐、WebGL 扩展完整）。
3. **但"值全对齐"不等于"能过"。** 对齐之后仍被拦，说明原因是
   **动态行为**（事件序列、采集轮次）而不是**静态值**。
   这个区分决定了下一步该改什么。
4. **空数据本身就是特征。** `events.mouse: []` 不是"少了个可选字段"，
   它是"这个用户从没动过鼠标"的强信号。
   补环境最容易漏的就是这类"应该有的动态数据"。
5. **反自动化检测已经在监听事件名了。**
   `driver-evaluate` / `webdriver-evaluate` / `selenium-evaluate` 三个
   自定义事件是专门用来钓 Selenium 的。
   所以即使用浏览器方案，也不能用 `Runtime.evaluate` 去注入东西。
