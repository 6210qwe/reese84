**#17 给出的种子公式（纯算的关键）**：

```js
var SC = window["Math"]["random"]() * 1073741824 | 0;
// 然后基于 SC 生成两个伪随机数组：
//   一个用于处理"参数对象"，一个用于处理"指纹对象"
// 加密手法：置换、异或、模运算
```

⇒ **`Math.random()` 会进指纹**。补环境里如果想控制编码结果，接管 `Math.random` 即可。

**#14 给出的"固定链接"机制（我一开始完全不知道）**：

> 除每次挑战下发的动态 sensor 路径外，还有一条**固定路径**：
> `GET 固定路径 → 拿到同一份 JS`；`POST 固定路径 → 载荷是上一轮的 token → 响应 token 不变`。
> 作者判断这是"查询有效期/激活"接口，且 **`old_token` 为空也能过**。

**我们实测验证了这一条在 airgreenland 上的形态**：

```
GET  /ieze-Buddieu-to-formes-from-our-he-bene-euer-The/          → 200  842710B text/javascript
GET  /ieze-Buddieu-to-formes-from-our-he-bene-euer-The/<40hex>?s= → 200  838308B text/javascript
```

⇒ **单词目录部分是稳定的，只有 40 位 hex 会轮换。**
所以 sensor **可以按目录缓存**（我们之前按完整路径缓存，一换 hex 就失效）。

但它没有可被我们找到的 POST 形态（试了 4 种 body 全部 400）。

## 7. 这份综述改变了什么

1. **判据换了**：从"有没有 token"改成"`X-Iinfo` 有没有 B 段"（`docs/11`）。
2. **补了两个从 2024 年就该补的检测项**：`toString` 链 + `getOwnPropertyNames`（`docs/08`）。
3. **发现 sensor 路径可按目录缓存**：单词目录稳定，只有 40 位 hex 轮换。
4. **确认 `Math.random()` 进指纹**：这是纯算路线唯一可用的"控制点"。
5. **确认"每次 reload 换编码函数"**：彻底放弃纯算，路线收敛到"跑原始 JS"。
