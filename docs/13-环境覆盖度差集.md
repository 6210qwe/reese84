# 环境覆盖度差集：从"猜哪个值错"改成"列出哪些能力不存在"

这一轮之前，我在同一个坑里转了很多圈：改一个值 → 跑一遍 → 还是 B12 → 再猜下一个。
问题是**错的值会报错，缺的能力不会**。sensor 读 `typeof navigator.mediaCapabilities` 拿到
`undefined` 之后不会抛异常，它会直接跳过整段采集，最后只是"载荷看起来正常但被判 bot"。

所以我写了个探针，把两个环境跑同一份 112 项清单，直接做差集。

文件：`tools/probe_coverage.js`

## 探针清单从哪来

不是我自己想的，是从三处拼的：

1. `PZz0203/Incapsula` 仓库的 `incapsula/reese84/schema.js` —— 这是 payload 的字段表，
   38 个顶层字段，每个都有完整类型定义。相当于拿到了"答案的目录"。
2. 52pojie《某航司 Reese84 补环境篇》（2025-09）里的 22 个采集函数清单。
3. 我自己踩过的坑。

字段表的价值在于：**它告诉你服务端要看什么**。比如里面明确有
`window_object_get_own_property_names_a` / `_b` / `_last_30` 三个字段，
说明它在采 `Object.getOwnPropertyNames(window)` 的结果。这条以前完全没意识到。

## 顺手挖出一个"写了但没接线"的 bug

`hardwareConcurrency` 为什么是 8？我明明做过 baseline 回放。

因为 `03-window.js` 里所有回放分支写的都是 `__CFG.baseline.xxx`，
而 `runner.js` **从来没有把 baseline 挂到 cfg 上**。`createBridge` 里
`baseline: BASELINE` 挂的是 bridge 自己的属性，不是 cfg 的。

于是那段"回放真实采样值"的代码一直是死代码，永远走 `|| 8` 的兜底。

修法一行：

```js
// bridge.js createBridge 开头
if (!cfg.baseline) cfg.baseline = BASELINE;
```

这类 bug 最难受：不报错、不告警，只是让指纹悄悄退回猜测值。
我前后跑了十几轮都没发现，因为它"看起来在工作"。

## window 属性数量差 947 项，怎么补

这是最大的一块。`getOwnPropertyNames(window)` 差 947 项，而 schema 里三个字段就采这个。

做法分两步：

**第一步，导出真实表。** `tools/dump_window_names.js` 用 CDP 在真实 Edge 上跑一遍，
把每个自有属性和它的 `typeof`、`Object.prototype.toString` 的 tag、`enumerable` 一起导出：

```
1239 个 window 自有属性
类型分布: {function: 1029, object: 180, number: 17, string: 3, boolean: 7, undefined: 3}
可枚举: 243
```

**第二步，按类型合成。** 装完自己手写的部分之后，遍历这张表，
凡是 `name in window` 为假的就补一个同类型的桩：

- `function` → 一个空构造器，过 `nativeClass()` 让 `toString` 出 `[native code]`
- `object` → `{}` 加对应 `Symbol.toStringTag`
- 数字/字符串/布尔 → 0 / '' / false
- 已存在的，只把 `enumerable` 对齐（这一步修 `Object.keys` 虚高）

结果：

| | 浏览器 | 修前 | 修后 |
|---|---|---|---|
| `getOwnPropertyNames(window)` | 1239 | 292 | **1253** |
| `Object.keys(window)` | 243 | 214 | **251** |
| 112 项不一致 | — | 27（9 项缺失） | **10（0 项缺失）** |

多出来的 14/8 项是我自己加的宿主钩子，无所谓。

## 一个改不动的细节

`enumerable` 对齐第一次写完没生效。原因很蠢：

```js
Object.defineProperty(w, name, {
  value: d.value, get: d.get, set: d.set,   // ← 同时给 value 和 get
  writable: d.writable, configurable: true, enumerable: en,
});
```

属性描述符只能二选一：数据属性（`value`/`writable`）或访问器（`get`/`set`）。
同时给直接 `TypeError`，而它在 `try/catch` 里面，被吞掉了，
表现就是"明明改了代码，数字一点没动"。

## 修完还是没过

诚实记录：112 项全绿之后重跑，仍然是

```
X-Iinfo: ... B12(14,0,0) U18
performance = {"1030820235": 597, "4203433130": 2, "total": 630}
payload = 34068
```

而且 payload 从 28000 涨到 34068 —— **比真实浏览器的 28412 还大 20%**。
说明我补的某项体积过头了（大概率是 `window_object_get_own_property_names` 那几个
列表，我们 1253 项里有 14 项是自己的名字）。

所以"环境覆盖度"是必要条件，不是充分条件。它把一批确实存在的假特征消掉了，
但服务端否掉我们的理由不在这 112 项里。

## 这个探针本身的复用价值

它不绑定 reese84。换任何站、任何厂商，只要换掉探针清单里那部分"业务相关"的项，
剩下 100 多项（API 存在性、函数形状、属性可枚举性）都是通用的。

所以它已经进了 `js-antibot-pipeline` skill 的固定动作：
**先跑差集，再动手改。** 差集没清干净之前，调参数纯属浪费。
